= image:./small-arc42-logo.png[arc42] Generator for arc42 Template Formats

If you want to use an arc42 template for your system, you **don't need to use this repo** - just use one of the templates you find on https://arc42.org/download.

== General Overview

The content (structure + embedded-help) of the arc42 template are maintained in the https://github.com/arc42/arc42-template repository. 


>See section [#generator-requirements] for a brief explanation of terminology and requirements.

== How to Build


This repository contains a Groovy-based build system that generates arc42 templates in multiple formats and languages from the Golden Master source.

**IMPORTANT: Docker is the only supported build approach.** All dependencies (Java, Groovy, Pandoc, cmark) are pre-configured in the Docker container.

>In theory it will be possible to run the build locally without Docker, but this is not supported and may lead to unexpected issues.


=== Prerequisites

* https://www.docker.com/[Docker] and Docker Compose installed
* Git (to clone the repository with submodules)

=== Quick Start

1. Clone this repository including submodules:
+
----
git clone --recurse-submodules git@github.com:arc42/arc42-generator.git
cd arc42-generator
----

2. Run the build using Docker Compose:
+
----
docker compose up
----
+
The build will:

* Update the arc42-template submodule (Golden Master)
* Generate templates in all supported languages and flavors
* Convert to 15+ output formats (HTML, Markdown, DOCX, PDF, etc.)
* Create distribution ZIP files in `arc42-template/dist/`
* Verify every ZIP and write a JUnit and HTML report to `build/reports/` (see <<verify,Verifying the Output>>)

Results are written to the local `build/` directory.


=== Building in GitHub Codespaces

Docker is the recommended approach even in GitHub Codespaces:

----
docker compose up
----

The container handles all Git ownership issues automatically, so you don't need to install any local dependencies.

=== Advanced Build Options

To rebuild the Docker image from scratch:

----
docker compose build --no-cache
----

To run individual build phases inside the container:

----
# Start an interactive shell in the container
docker compose run --rm arc42-builder /bin/bash

# Then run individual phases
groovy build.groovy templates      # Generate templates only
groovy build.groovy convert        # Convert to output formats
groovy build.groovy distribution   # Create distribution ZIPs
groovy build.groovy verify         # Verify the ZIPs, write reports (exit 1 on failures)
----

=== Building Other Templates (e.g. req42)

The generator is not tied to arc42. Everything project-specific lives in the config file:

* `project.name` - base name of the main document (`<LANG>/<name>.adoc`) and of all generated files and ZIPs
* `project.featurePrefix` - prefix of the feature markers, e.g. `[role="arc42help"]` and `ifdef::arc42help[]`, and of the about page (`about-arc42.adoc`)
* `project.logo` - the only image copied into the plain style
* `goldenMaster.sourcePath` and `distribution.targetPath` - location of the sources and of the ZIPs

`buildconfig.groovy` holds the arc42 values. Another template keeps a complete copy of this file (all sections) in its own repository and follows the layout of `arc42-template`: `<LANG>/<name>.adoc`, `<LANG>/adoc/`, `<LANG>/images/` and `<LANG>/version.properties`.
Paths in a config file are relative to the directory of that file, including the `build/` output.

Mount the template repository into the container and pass its config:

----
docker compose run --rm -v /path/to/req42-framework:/project arc42-builder \
  groovy build.groovy --config=/project/buildconfig.groovy
----

=== Verifying the Output

The fifth build phase `verify` inspects every distribution ZIP in `arc42-template/dist/` and the
Golden Master itself. It runs automatically at the end of `docker compose up`. To run only the
verification, for example against the ZIPs that are already committed:

----
# all formats, all languages (about 5 seconds)
docker compose run --rm arc42-builder groovy build.groovy verify

# one format only
docker compose run --rm arc42-builder groovy build.groovy verify --format=html

# another template project (see "Building Other Templates")
docker compose run --rm -v /path/to/req42-framework:/project arc42-builder \
  groovy build.groovy verify --config=/project/buildconfig.groovy
----

The console prints one line per format with pass/warn/fail counts, then every failed test case
with its rule ids, then the report paths. The exit code is 1 if any test case failed, so the
verification also gates CI.

==== Reading the reports

* `build/reports/verify.html` - open it in a browser. The header names the generator and Golden
  Master commits. The matrix has one row per language with its template version (`revnumber` and
  `revdate` from `version.properties`) and one column per format plus `source`; each cell shows
  the `plain` and `with-help` result as a coloured mark (green pass, yellow warn, red fail,
  grey missing). Below the matrix every finding is listed once per rule id with the affected
  outputs and up to three examples with file name and line number. Errors are expanded, warnings
  collapsed.
* `build/reports/junit/TEST-<format>.xml` - one Surefire-style JUnit file per format plus
  `TEST-source.xml`. Test case names carry the version, e.g. `EN-with-help [9.0-EN]`. Any CI
  server that understands JUnit XML (GitHub Actions, GitLab, Jenkins) can display them.
* A run with `--format=<f>` writes `verify-<f>.html` next to `verify.html` and updates only
  `TEST-<f>.xml` and `TEST-source.xml`, so the last full matrix stays intact.

==== What is checked

* **Completeness** (`zip.*`): every language × style × format ZIP exists, is non-empty, contains
  the primary file (twelve chapter files for multi-page formats) and, for with-help, the images
* **Structure** (`structure.*`): twelve chapters, heading counts compared with the reference
  language (warning only), help text present only in with-help, template version present in the text
* **Markdown purity** (`md.*`): no pandoc-only syntax (`:::` divs, `{#id}` attributes), no raw
  HTML beyond the per-format allow list, no empty heading, images resolve, parses as CommonMark
* **HTML** (`html.*`): one `<html>` and `<body>`, non-empty `<title>`, UTF-8 charset, images
  resolve, local `#anchors` have a target (warning)
* **DOCX and EPUB** (`docx.*`, `epub.*`): the package opens, its XML parses, manifest items and
  media are present
* **Source** (`src.*`): `version.properties` complete, main document present, twelve chapter
  files, every `include::` and `image::` target exists

Every finding names its rule id, e.g. `md.rawHtml`. The full list with default severities is the
`DEFAULT_SEVERITY` map at the top of `lib/Checks.groovy`.

==== Adjusting severities

Rule severities live in the `verify` block of `buildconfig.groovy`. To downgrade a rule to a
warning while the generator is being fixed, or to switch it off:

----
verify {
    severity = ['md.rawHtml': 'warn', 'md.frontMatter': 'off']
}
----

The same block sets the reference language (`EN`), the chapter count (12), the report directory
(`build/reports`) and the HTML tags tolerated per Markdown format (`allowedHtml`).

==== Known state

The verification is intentionally red on the current Golden Master: the Markdown formats still
contain pandoc-only syntax and raw HTML, the multi-page with-help ZIPs lose their help text, and
several languages reference images that only exist in `EN/images`. These are generator and
content defects tracked separately; the verifier documents them until they are fixed.

Verifying the verifier itself:

----
docker compose run --rm arc42-builder groovy test-verifier.groovy
----


=== Docker Image Details

The Docker image is optimized for size and build speed:

* **Multi-stage build**: Separates build-time and runtime dependencies
* **Cached dependencies**: Groovy Grape cache pre-populated during image build
* **Minimal runtime**: Alpine Linux 3.20 with only essential tools
* **Final image size**: ~564MB

The container includes:

* Java Runtime (OpenJDK 21)
* Groovy 5.0.3
* Pandoc 3.7.0.2 (document converter)
* cmark (CommonMark validator)
* AsciidoctorJ (AsciiDoc processor)


**No local installation of Java, Groovy, or Pandoc is required or supported.**


== General Requirements

=== Requirements Concerning the Generator

We need to build the template for several output formats and natural languages from a single source (the Golden Master in arc42-template).

* Technical formats: docx, Markdown (with numerous variants), AsciiDoc, reStructuredText, Textile, HTML
* Variantes (aka _flavours_): withHelp (embedded help texts), plain (no help texts)
* Natural languages: English, German, Spanish, French, Italian, Portuguese, Chinese and others.
