= image:./small-arc42-logo.png[arc42] Generator for arc42 Template Formats

If you want to use an arc42 template for your system, you **don't need to use this repo** - just use one of the templates you find on https://arc42.org/download.

== General Overview

The content (structure + embedded-help) of the arc42 template are maintained in the https://github.com/arc42/arc42-template repository. 


>See section [#generator-requirements] for a brief explanation of terminology and requirements.

== How to Build


This repository contains a Groovy-based build system that generates arc42 templates in multiple formats and languages from the Golden Master source.

**IMPORTANT: Docker is the only supported build approach.** All dependencies (Java, Groovy, Pandoc, cmark) are pre-configured in the Docker container.

>In theory it will be possible to run the build locally without Docker, but this is not supported and may lead to unexpected issues.


=== Prerequisites

* https://www.docker.com/[Docker] and Docker Compose installed
* Git (to clone the repository with submodules)

=== Quick Start

1. Clone this repository including submodules:
+
----
git clone --recurse-submodules git@github.com:arc42/arc42-generator.git
cd arc42-generator
----

2. Run the build using Docker Compose:
+
----
docker compose up
----
+
The build will:

* Check out the arc42-template submodule (Golden Master) at the commit recorded in this repository
* Validate the Golden Master (conditionals, help blocks, images, version.properties) and stop on errors
* Generate templates in all supported languages and flavors
* Convert to 17 output formats (HTML, Markdown variants, DOCX, EPUB, LaTeX, reStructuredText, Textile, DocBook, AsciiDoc)
* Stop on Asciidoctor or Pandoc diagnostics (missing includes, missing images, ...)
* Validate CommonMark markdown and image references
* Create distribution ZIP files in `arc42-template/dist/`

Every run starts from a clean `build/` output, so nothing from an earlier run ends up in the ZIPs. The output is reproducible: unchanged content produces byte-identical files and ZIPs (timestamps come from `SOURCE_DATE_EPOCH` or the last commit of the Golden Master, not from the build time).

Results are written to the local `build/` directory.


=== Building in GitHub Codespaces

Docker is the recommended approach even in GitHub Codespaces:

----
docker compose up
----

The container handles all Git ownership issues automatically, so you don't need to install any local dependencies.

=== Advanced Build Options

To rebuild the Docker image from scratch:

----
docker compose build --no-cache
----

To run individual build phases inside the container:

----
# Start an interactive shell in the container
docker compose run --rm arc42-builder /bin/bash

# Then run individual phases
groovy build.groovy templates      # Generate templates only
groovy build.groovy convert        # Convert to output formats
groovy build.groovy distribution   # Create distribution ZIPs

# Options
groovy build.groovy convert --format=html          # one format only
groovy build.groovy --failure-level=error          # fail only on errors, not on warnings (default: warn)
groovy build.groovy templates --lint=warn          # report Golden Master problems without failing
groovy build.groovy --parallel=false               # sequential conversion
----

To build the latest `master` of the Golden Master instead of the recorded submodule commit, run the build script with `./build-arc42.sh --update-template` (or set `UPDATE_TEMPLATE=1`).

=== Building Other Templates (e.g. req42)

The generator is not tied to arc42. Everything project-specific lives in the config file:

* `project.name` - base name of the main document (`<LANG>/<name>.adoc`) and of all generated files and ZIPs
* `project.featurePrefix` - prefix of the feature markers, e.g. `[role="arc42help"]` and `ifdef::arc42help[]`, and of the about page (`about-arc42.adoc`)
* `project.logo` - the only image copied into the plain style
* `goldenMaster.sourcePath` and `distribution.targetPath` - location of the sources and of the ZIPs

`buildconfig.groovy` holds the arc42 values. Another template keeps a complete copy of this file (all sections) in its own repository and follows the layout of `arc42-template`: `<LANG>/<name>.adoc`, `<LANG>/adoc/`, `<LANG>/images/` and `<LANG>/version.properties`.
Paths in a config file are relative to the directory of that file, including the `build/` output.

Mount the template repository into the container and pass its config:

----
docker compose run --rm -v /path/to/req42-framework:/project arc42-builder \
  groovy build.groovy --config=/project/buildconfig.groovy
----

=== Build Validation

The build fails on problems in the sources and in the conversion:

* **Golden Master lint** (before generation): unbalanced `ifdef::arc42help[]`/`endif::arc42help[]`, help blocks that are not wrapped in a conditional, image references without a file in `<LANG>/images/`, and incomplete `version.properties` are errors; a chapter set or help-block count that differs from EN is a warning. Use `--lint=warn` to report instead of fail.
* **Diagnostics** (after conversion): Asciidoctor log records (e.g. a missing include) and Pandoc warnings (e.g. an image it could not embed into DOCX or EPUB) are printed with file and line. Records at `--failure-level` (default `warn`) or above fail the build.
* **Clean output**: the output directories of a phase are deleted before the phase runs.

`build-arc42.sh` additionally validates the generated Markdown with `cmark` (non-fatal, skipped when `cmark` is not installed) and the image references of the with-help Markdown (fatal).



=== Docker Image Details

The Docker image is optimized for size and build speed:

* **Multi-stage build**: Separates build-time and runtime dependencies
* **Cached dependencies**: Groovy Grape cache pre-populated during image build
* **Minimal runtime**: Alpine Linux 3.20 with only essential tools
* **Final image size**: ~564MB

The container includes:

* Java Runtime (OpenJDK 21)
* Groovy 5.0.3
* Pandoc 3.7.0.2 (document converter, pinned release binary with checksum)
* cmark (CommonMark validator)
* AsciidoctorJ 2.5.10 (AsciiDoc processor, bundles Asciidoctor 2.0.20)


**No local installation of Java, Groovy, or Pandoc is required or supported.**


== General Requirements

=== Requirements Concerning the Generator

We need to build the template for several output formats and natural languages from a single source (the Golden Master in arc42-template).

* Technical formats: docx, Markdown (with numerous variants), AsciiDoc, reStructuredText, Textile, HTML
* Variantes (aka _flavours_): withHelp (embedded help texts), plain (no help texts)
* Natural languages: English, German, Spanish, French, Italian, Portuguese, Chinese and others.
